在大模型（LLM）的对话交互中，`system`、`user` 和 `assistant` 是三种核心角色，它们共同构成了模型理解上下文和生成回复的基础。

你可以把它们想象成**剧本中的不同角色**，或者**公司里的不同职能**。以下是它们的具体区别：

### **🤖 System (系统提示词)**

- **身份**：**“幕后导演”**或**“设定者”**。
- **作用**：它通常是对话的**第一条**消息，用户往往看不见（或者在设置里配置）。它的作用是给大模型“洗脑”或“定调”。
- **内容**：
  - 规定模型的人设（例如：“你是一个专业的Python程序员”、“你是一个只会说古文的诗人”）。
  - 设定行为准则（例如：“回答要简短”、“严禁回答政治敏感话题”、“必须用JSON格式输出”）。
  - 提供背景知识（例如：“当前时间是2026年...”）。
- **特点**：它的权重很高，贯穿整个对话，用来约束模型在后续对话中的表现。

### **🙋 User (用户提示词)**

- **身份**：**“提问者”**或**“人类”**。
- **作用**：这是实际使用模型的人发出的指令。
- **内容**：
  - 具体的问题（例如：“解释一下量子力学”）。
  - 任务指令（例如：“帮我把这段话翻译成英文”）。
  - 对上一轮回答的反馈（例如：“不对，请重新解释”）。
- **特点**：这是对话的驱动力，模型需要根据System的设定来回答User的问题。

### **🗣️ Assistant (助手提示词)**

- **身份**：**“大模型本身”**。
- **作用**：这是模型生成的回复内容。
- **内容**：
  - 模型根据System的设定和User的问题，计算出的最合适的回答。
- **特点**：在对话历史中，Assistant的回复会变成“上下文”的一部分。当用户问下一个问题时，模型会回顾之前Assistant说过的话，以保持对话的连贯性。

------

### **📌 总结与类比**

为了更直观地理解，我们可以用一个**“公司场景”**来类比：

| 角色          | 类比                | 职责                             | 示例内容                                          |
| :------------ | :------------------ | :------------------------------- | :------------------------------------------------ |
| **System**    | **老板/岗位说明书** | 制定规则，设定人设，划定边界。   | "你是公司的客服，态度要热情，不能说脏话。"        |
| **User**      | **客户**            | 提出需求，发起询问。             | "我的快递怎么还没到？"                            |
| **Assistant** | **员工**            | 根据老板的规矩，回答客户的问题。 | "亲，帮您查了一下，快递正在运输中，请耐心等待哦~" |

### **💡 为什么区分这三者很重要？**

对于开发者来说，区分这三者是为了**控制模型的行为**。

- 如果把所有话都混在一起发给模型，模型可能会分不清哪句是规则，哪句是问题。
- 通过明确标记 `System`，开发者可以确保模型**“入戏”**（比如扮演一个医生），无论 `User` 怎么问，模型都会保持医生的口吻回答。

在代码调用（如OpenAI API）中，它们的格式通常长这样：

```json
[
  {"role": "system", "content": "你是一个乐于助人的数学老师。"},
  {"role": "user", "content": "1+1等于几？"},
  {"role": "assistant", "content": "1+1等于2。"},
  {"role": "user", "content": "谢谢！"}
]
```
