# YOLOv8 ONNX Runtime CUDA 环境段错误（Segmentation fault）排查与解决

## 1. 问题现象与环境背景

### 1.1 错误现象

在 Conda 虚拟环境（`Yolov8_InfraRed`）中运行 YOLOv8 ONNX 模型推理脚本 `demo.py` 时，程序直接崩溃并抛出 C++ 级别的段错误（Segmentation fault）：

```bash
(Yolov8_InfraRed) shi19@AIPC:~/Yolov8_infrared/ship_demo_v10/ship_demo$ python3 demo.py --weights models/last_nohalf_nonms.onnx --source datasets/ISSD/JPEGImages/
Segmentation fault (core dumped)
```

### 1.2 崩溃日志（借助 `PYTHONFAULTHANDLER=1`）

使用 `PYTHONFAULTHANDLER=1` 打印底层的 C/C++ 崩溃调用栈。

```bash
Fatal Python error: Segmentation fault

Current thread 0x000076bc380a6740 (most recent call first):
  File ".../onnxruntime/capi/onnxruntime_inference_collection.py", line 584 in _create_inference_session
  File ".../onnxruntime/capi/onnxruntime_inference_collection.py", line 485 in __init__
  File ".../ship_detector.py", line 33 in make_session
  File ".../demo.py", line 54 in main
  File ".../demo.py", line 89 in <module>
```

### 1.3 初始环境配置

- **显卡驱动**：NVIDIA Driver 592.82 / CUDA 13.1 支持
- **Python 依赖库（问题解决前）**：
  - `onnxruntime-gpu`: 1.23.2
  - `numpy`: 2.2.6

## 2. 根因分析 (Root Cause Analysis)

1. **NumPy 2.x ABI 兼容性冲突（首要诱因）** 环境中原本安装的是 `numpy 2.2.6`。NumPy 2.0 对底层 C-API 进行了重大重构，导致许多依赖旧版 C-API 编译的深度学习底层扩展库在运行时产生内存地址错乱，从而直接引发内存段错误（Segmentation fault）。
2. **ONNX Runtime GPU 与 CUDA 动态库二进制冲突**`onnxruntime-gpu 1.23.2` 版本在初始化推理会话（`_create_inference_session`）时，与当前的 CUDA/cuDNN 运行时环境存在兼容性问题。

## 3. 完整解决措施（双管齐下）

为了让 Conda 虚拟环境恢复正常工作，同时执行了以下两项关键修复措施：

### 措施一：降级 NumPy 到 1.x 版本

避开 NumPy 2.x 的 ABI 重构导致的 C 扩展冲突：

```bash
pip3 install "numpy<2.0"
```

*(降级后成功安装 `numpy-1.26.4`)*

### 措施二：降级 `onnxruntime-gpu` 到稳定版本

将过于超前的 `onnxruntime-gpu 1.23.2` 降级至在 CUDA 12 环境下表现极为稳定的 **`1.19.2`** 版本：

```Bash
pip3 uninstall -y onnxruntime onnxruntime-gpu
pip3 install onnxruntime-gpu==1.19.2
```

## 4. 验证结果

完成上述两项调整后，重新运行推理脚本，ONNX 模型的 GPU 推理会话顺利完成初始化，程序恢复正常工作：

```bash
python3 demo.py --weights models/last_nohalf_nonms.onnx --source datasets/ISSD/JPEGImages/
```

## 5. 避坑总结

- **NumPy 升级风险**：在使用较旧或特定版本的深度学习推理库（如 ONNX Runtime、TensorRT 等）时，盲目升级到 NumPy 2.x 极易由于 C-API 不兼容引发隐蔽的段错误。保持 NumPy 1.26.x 是当前许多工业级部署的稳妥选择。
- **双剑合璧**：排查 C++ 底层 Crash 时，往往需要同时关注数据基础库（NumPy）**与**框架计算库（ONNX Runtime / TensorRT）的版本匹配。
