# 数据标注格式

---

在目标检测项目中，**YOLO**、**CreateML** 和 **PascalVOC** 是目前最主流的三种数据标注格式。

它们在文件结构、坐标定义和应用场景上有显著区别。

以下是这三种格式的详细对比：



## **一、 格式详细解析**

### **1. YOLO 格式 (.txt)**



- **文件结构**：**一图一文件**。每个图片对应一个同名的 `.txt` 标签文件。

- **坐标格式**：采用**归一化相对坐标**（中心点 + 宽高）。

- **单行格式**：

  ```
  class_id x_center y_center width height
  ```

  - `class_id`：类别的索引（从 0 开始）。
  - `x_center`、`y_center`、`width`、`height`：都是经过归一化的相对值，范围在 `0.0` 到 `1.0` 之间。例如，`x_center` = 目标中心点 X 坐标 / 图片总宽度。

- **特点**：文件体积极小，解析速度极快，非常适合 YOLO 系列模型的实时训练与推理。使用时通常需要配合一个<mark>**记录类别名称**</mark>的配置文件（如 `data.yaml` 或 `classes.txt`）。

  

### **2. CreateML 格式 (.json)**



- **文件结构**：**多对一**或**整体单文件**。通常将整个数据集（或子集）的所有标注信息存储在一个 `.json` 文件中。

- **坐标格式**：通常采用**左上角坐标 + 宽高**（x, y, width, height）。

- **数据结构**：使用标准的 JSON 数组格式，包含 `image`（图片文件名）和 `annotations`（包含类别、坐标的数组）等字段。

- **特点**：这是苹果生态专属格式，专为 Apple Core ML 框架设计，用于在 macOS/iOS 设备上训练和部署机器学习模型。

  

### **3. PascalVOC 格式 (.xml)**



- **文件结构**：**一图一文件**。每个图片对应一个同名的 `.xml` 标签文件。
- **坐标格式**：采用**绝对像素坐标**（左上角 + 右下角）。
- **标签内容**：使用 XML 标签，包含图片文件名、长宽、通道数等完整的元数据，以及每个目标的类别名称（`<name>`）、边界框绝对坐标（`<xmin>`, `<ymin>`, `<xmax>`, `<ymax>`），甚至可以包含是否被截断（truncated）、是否难以识别（difficult）等辅助信息。
- **特点**：自描述性强，人类可读性极高，是传统计算机视觉和学术研究（如 VOC 竞赛、Faster R-CNN、SSD 等模型）的通用标准格式。缺点是文件体积庞大，存储效率较低。

------



## **二、 核心维度对比总结**

---

|   对比维度   |                YOLO 格式 (.txt)                |            CreateML 格式 (.json)             |             PascalVOC 格式 (.xml)              |
| :----------: | :--------------------------------------------: | :------------------------------------------: | :--------------------------------------------: |
| **坐标体系** | **归一化相对坐标** (中心点 `x,y` + 宽高 `w,h`) | **绝对像素坐标** (左上角 `x,y` + 宽高 `w,h`) | **绝对像素坐标** (左上角 `x,y` + 右下角 `x,y`) |
| **文件结构** |       图片与标签一一对应 (1图对应1 txt)        |      整合在一个总 JSON 文件中 (多对一)       |       图片与标签一一对应 (1图对应1 xml)        |
| **文件大小** |            极小（纯数字，存储极快）            |              中等（JSON 格式）               |           较大（包含大量元数据标签）           |
|  **元数据**  |           无（不含图片尺寸等元数据）           |                 包含完整信息                 |        包含完整元数据（图片名、长宽等）        |
| **核心优势** |           训练读取速度极快，文件极简           |          专为苹果 Core ML 生态优化           |        通用性强，信息完整，方便人工校验        |
| **适用场景** |       **YOLO 系列模型训练** (v5/v8/11等)       |        苹果移动端/桌面端 Core ML 应用        |     传统 CV 研究、Faster R-CNN/SSD 等模型      |

### **总结建议**

- 若你使用的是 YOLO11 进行目标检测，**YOLO (.txt) 格式**是最直接、最高效的选择。

- 若你在开发苹果生态下的 App，则必须使用 CreateML；

- 若你是做学术研究或需要兼容多种传统深度学习框架，PascalVOC 依然是通用性最好的基准格式。
