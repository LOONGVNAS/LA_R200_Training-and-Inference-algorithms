# YOLO 11 优化器

----

<img width="452" height="29" alt="image" src="https://github.com/user-attachments/assets/2aab7a58-12a0-43d3-a69f-2b4f1e164c75" />


优化器（Optimizer）是模型训练中的**参数更新引擎**，负责回答一个核心问题：**既然损失函数告诉我们"预测错了多少"，那该怎么调整这几百万个参数，才能让下一次预测更准一点？**

## **在训练循环里的位置**

一次完整的训练迭代是这样的：

```
前向传播 → 算损失 → 反向传播算梯度 → 【优化器登场】更新权重 → 下一轮
```

具体到代码：

```python
loss = criterion(output, target)   # 算出错了多少
loss.backward()                    # 反向传播，算出每个参数的梯度
optimizer.step()                   # ← 优化器根据梯度决定怎么改权重
optimizer.zero_grad()              # 清空梯度，准备下一轮
```

`optimizer.step()` 这一行，就是优化器真正干活的地方。

## **最朴素的思路：SGD**

**SGD（随机梯度下降）** 的逻辑最直白：梯度指向损失上升最快的方向，那就往反方向走一小步。

<img width="201" height="36" alt="image" src="https://github.com/user-attachments/assets/7ee7ec11-9940-4f5a-b41b-01bbcce08a3e" />


其中 η就是**学习率（learning rate）**，控制步子迈多大。

打个比方：你蒙着眼站在山坡上想下到谷底，SGD 就是"用脚探一下哪个方向最陡，往那边迈一步"。

步子太大可能跨过谷底来回震荡，步子太小则要走到天荒地老。

## **SGD 的毛病与 Adam 的改进**

纯 SGD 有两个痛点：

**1. 所有参数用同一个学习率**

但实际情况是，有的参数梯度很大（需要小步走），有的参数梯度极小（需要大步走）。

比如在你的 YOLO OBB 任务里，角度预测分支和分类分支的梯度量级可能差好几个数量级。

**2. 遇到鞍点或平坦区域会卡住**

损失曲面上有些区域坡度接近零，SGD 走几步就几乎不动了，但实际上那里可能只是"平台"，不是真正的最低点。

**Adam** 用两个机制同时解决了这些问题：

|         机制         |          作用          |                  通俗理解                  |
| :------------------: | :--------------------: | :----------------------------------------: |
| **动量（Momentum）** |    累积历史梯度方向    |   像滚下坡的球，有惯性，能冲过小坑和平台   |
|   **自适应学习率**   | 给每个参数单独调学习率 | 梯度大的参数自动减小步长，梯度小的自动放大 |

Adam 内部维护两个状态：一阶矩 m（梯度的指数移动平均，即"动量"）和二阶矩 v （梯度平方的移动平均，即"步长缩放因子"）。

## **常见优化器对比**

|       优化器       |             特点             |              适用场景               |
| :----------------: | :--------------------------: | :---------------------------------: |
|      **SGD**       |  简单、收敛慢、易陷局部最优  |         教学演示、简单任务          |
| **SGD + Momentum** |      加惯性，能跳出浅坑      |       CNN 图像分类的经典选择        |
|      **Adam**      | 自适应、收敛快、几乎不用调参 |   通用首选，Transformer/检测任务    |
|     **AdamW**      |     Adam + 解耦权重衰减      | **现代深度学习主流**，YOLO 默认推荐 |
|    **RMSprop**     |         Adam 的前身          |            循环神经网络             |

**AdamW 为什么比 Adam 好？** 原版 Adam 的 L2 正则化会被自适应学习率"缩放"，导致正则效果不稳定。

AdamW 把权重衰减从梯度更新里解耦出来单独执行，正则效果更可控，泛化性能更好。

这也是之前给 YOLO11-OBB 训练代码里推荐 `optimizer='AdamW'`。

## **关于表格里的 "auto"**

截图里默认值是 `auto`，这在 Ultralytics 框架里有特定含义：

- **`auto`**：框架根据训练配置自动选择。具体逻辑是——若训练轮数较少（默认 < 100 epoch），用 **AdamW**（收敛快，小数据集友好）；若轮数较多，用 **SGD + Momentum**（长期训练泛化更好）
- 可以显式指定 `optimizer='SGD'`、`'Adam'`、`'AdamW'`、`'RMSProp'`、`'NAdam'`、`'Adamax'`、`'LSGD'` 等

## **实践建议**

结合在做的 YOLO11-OBB 遥感/航拍任务：

**1. 小数据集或快速验证** → 用 `AdamW`，收敛快，对超参不敏感，10~20 epoch 就能看到明显效果

**2. 大数据集追求最终精度** → 用 `SGD + Momentum`，配合 `cos_lr=True`（余弦退火学习率），训练 150+ epoch，通常能比 Adam 高出 1~2 个点 mAP

**3. 学习率要跟着优化器调**

| 优化器 | 推荐 lr0 |
| :----: | :------: |
|  SGD   |   0.01   |
|  Adam  |  0.001   |
| AdamW  |  0.001   |

Adam 类优化器自带步长缩放，学习率要设小一个数量级，设成 0.01 容易直接发散。

**4. 权重衰减（weight_decay）**

- SGD 常用 0.0005
- AdamW 常用 0.01（因为解耦了，数值要比 SGD 大）



# 航拍小目标的场景

----

航拍小目标 + OBB 这套组合，调优的核心难点不在单个参数，而在**参数之间是强耦合的**：你改了数据增强强度，等效学习率就变了；改了优化器，学习率量级和轮数策略都要跟着动。

下面按"为什么耦合 → 怎么配 → 调参顺序"三层展开。

## **一、先认清航拍小目标的四个矛盾**



|           矛盾           |                             表现                             |                         对调优的影响                         |
| :----------------------: | :----------------------------------------------------------: | :----------------------------------------------------------: |
|  **目标极小 vs 下采样**  | 几万像素的图里车只有 10~20 px，P5 头下采样 32 倍后特征几乎消失 |         必须用大 `imgsz`，但大图又拖慢训练、易爆显存         |
| **方向任意 vs 标注规范** |           车辆/飞机朝向 0~180° 全覆盖，需 OBB 建模           | 旋转增强 `degrees` 必须开足，但角度定义要统一，否则 Loss 不降 |
| **目标密集 vs 增强破坏** | mosaic 拼 4 图提升小目标样本量，但拼缝会切断长条目标、错切会扭曲航向 |              mosaic/shear 是双刃剑，需后期关闭               |
|   **背景复杂 vs 误检**   |                    屋顶、树影易被认成车辆                    |         需 mixup + 强负样本挖掘，但又会拉低收敛速度          |

这四个矛盾决定了：**没有"一套参数通吃"，只有"分场景的两三套配置"**。

## **二、参数耦合关系（最关键的一张表）**

调参时任何一项变化都会牵动其他项，孤立调参是新手翻车的主因：

|            调整的            |       必须联动检查的       |                             原因                             |
| :--------------------------: | :------------------------: | :----------------------------------------------------------: |
|         `optimizer`          |         `lr0` 量级         |  SGD 用 0.01，Adam/AdamW 用 0.001，错一个量级直接发散或不动  |
|            `lr0`             | `warmup_epochs` + `cos_lr` | 大 lr 配短 warmup 前期梯度爆炸；长训练配 cos_lr 才能后期收敛 |
|         `mosaic=1.0`         |       `close_mosaic`       | 全程开 mosaic，最后阶段 Loss 在拼缝处震荡，必须收尾关 N epoch |
| 增强强度↑（scale/hsv/mixup） | `epochs`↑、`weight_decay`↑ |      增强是隐式正则，加增强等于加正则，要训得更久才收敛      |
|           `imgsz`↑           |  `batch`↓、`lr0` 可能要调  |   大图吃显存，batch 减半会改变等效梯度噪声，lr 需相应微调    |
|        OBB `degrees`↑        |       角度标注统一性       | 增强越强，对标注角度方向一致性越敏感，否则模型学不到稳定角度分布 |

## **三、三套可直接落地的配置**

**配置 A：快速验证 / 小数据集（<5k 图，先跑通看效果）**

|         参数          |      值      |
| :-------------------: | :----------: |
|       optimizer       |    AdamW     |
|       lr0 / lrf       | 0.001 / 0.01 |
|     warmup_epochs     |      3       |
|        epochs         |    50~80     |
|         imgsz         |     1024     |
|         batch         |     8~16     |
| mosaic / close_mosaic |   1.0 / 10   |
|  degrees（OBB 关键）  |     180      |
|        cos_lr         |     True     |

> AdamW 对超参不敏感，小数据集 50 epoch 内就能看到可用 mAP，适合先建立 baseline。

**配置 B：大数据集 / 追求最终精度（>20k 图，正式打榜）**

|         参数          |         值          |
| :-------------------: | :-----------------: |
|       optimizer       | SGD（momentum 0.9） |
|       lr0 / lrf       |     0.01 / 0.01     |
|     weight_decay      |       0.0005        |
|     warmup_epochs     |          5          |
|        epochs         |       150~300       |
|         imgsz         |        1280         |
|         batch         |  视显存，尽量 ≥16   |
| mosaic / close_mosaic |      1.0 / 20       |
|         mixup         |      0.1~0.15       |
|        cos_lr         |        True         |
|       patience        | 50（早停防过拟合）  |

> 经验规律：大数据长训练下 SGD 通常比 Adam 高出 1~2 个点 mAP，但代价是训练时间翻倍、对 lr 更敏感。**先用 A 跑通，再迁到 B 提精度**，不要在 B 配置上从零摸索。

**配置 C：小目标专项强化（精度瓶颈卡在召回上）**

在 B 的基础上叠加针对小目标的增强组合：

|    参数     |         值          |                   作用                   |
| :---------: | :-----------------: | :--------------------------------------: |
|    scale    | 0.5~0.9（放大范围） |            让模型见到更多尺度            |
|  translate  |       0.2~0.3       |      配合 mosaic 提升小目标出现频率      |
| copy_paste  |       0.2~0.3       | 把已有小目标贴到其它图，定向增广稀有类别 |
| multi_scale |        True         | 训练时随机变尺度，逼网络学到尺度不变特征 |
|    imgsz    | 1536（若显存允许）  |        直接保住小目标特征图分辨率        |

> copy_paste 是航拍密集小目标场景里性价比最高的一项，能显著补长尾类别的召回，但会减慢收敛，需把 epochs 同步加大。

## **四、学习率调度：航拍长训练的两条硬规则**

1. **warmup 不能省**。大图 + OBB 的初始梯度方差很大，没有 warmup 前几个 iter 极易把预训练权重打崩。Ultralytics 默认 `warmup_momentum`/`warmup_bias_lr` 配合 `warmup_epochs=3~5` 即可，一般不用手调。
2. **长训练首选 cos_lr，而非 step 衰减**。余弦退火在后期平滑降 lr，有助于在鞍点附近稳定收敛，对航拍这种数据分布复杂的任务比阶梯衰减更稳。短验证训练用默认衰减也行。

## **五、OBB 专属的调优坑（与水平框最大的差异）**

- **degrees 与 angle loss 是一对**：旋转增强拉到 180° 能覆盖全航向，但前提是你的标注角度定义统一。增强一开，标注方向不一致的样本会被模型当成噪声，表现为角度分支 Loss 居高不下。建议训练前先抽样可视化标注角度分布确认。
- **shear（错切）对 OBB 要调小或设 0**：错切会扭曲目标的真实朝向，与角度标签产生矛盾，航拍长条目标（船只、输电线）尤其受影响。把 shear 控制在 0~2 度，或干脆关掉。
- **imgsz 与角度分辨率的隐性矛盾**：图放大能救小目标，但 OBB 头对边角的亚像素定位精度要求高，过大图若 batch 太小反而让角度回归不稳定，需要在二者间找平衡。

## **六、推荐的调参执行顺序（避免乱调）**

不要一次动多个参数，按这个依赖顺序逐层收敛：

1. 先定 **imgsz + batch**（受显存和硬件硬约束，龙芯/国产 GPU 上 batch 往往偏小，这会改变等效梯度噪声，所以这步最先锁死）。
2. 再定 **优化器 + lr0 + 轮数**，用配置 A 建立 baseline，确认 Loss 正常下降、标注无误。
3. 然后开 **mosaic / degrees / close_mosaic**，验证 mAP 是否提升，提不动就把 close_mosaic 调大。
4. 最后才是 **copy_paste / mixup / multi_scale / scale** 这些精修增强，逐项加、逐项验，每次只动一项。
5. 收尾若卡在召回，走配置 C；卡在精度，回到配置 B 拉长 epochs 并配合 patience 早停。
