论文里说的 **concatenation-based model**，也就是**大量依靠通道维度 concat 来融合特征的模型**。

### **为什么叫“拼接模型”？**

YOLOv7 的 Backbone 和 Neck 里有很多地方会把不同分支的特征图按通道维度拼起来，比如：

- ELAN / E-ELAN 模块内部的多分支输出拼接；
- FPN / PANet 里不同层级特征的拼接；
- 跨阶段连接时把浅层特征和深层特征拼在一起。

这种结构的特点不是简单的 `Add`，而是 **concat**：拼接后通道数会增加，后续层的输入宽度也会跟着变。

### **它和普通残差模型有什么区别？**

表格

| 类型   | 特征融合方式             | 缩放时更敏感的点               |
| :----- | :----------------------- | :----------------------------- |
| 残差型 | Add / Identity           | 深度、宽度相对独立             |
| 拼接型 | Concatenate              | 深度变化会牵连通道宽度         |
| YOLOv7 | ELAN/E-ELAN + PANet 拼接 | 必须同时考虑深度、宽度、分辨率 |

### **为什么 YOLOv7 要专门提它？**

因为拼接模型不能像 EfficientNet 那样简单地统一缩放。
若你只把计算块堆得更深，ELAN 模块输出的通道数会变多，后面 transition 层的输入宽度也会跟着变，可能导致硬件利用率下降、结构比例失衡。

所以 YOLOv7 的复合缩放会区分两类层：

- **计算块内部**：主要缩放深度，比如增加 ELAN/E-ELAN 堆叠；
- **过渡层 / 拼接边界**：主要缩放宽度，保证 concat 后的通道维度仍然协调。

所以“拼接模型”在这里就是：**以 concatenate 为主要特征融合方式的网络结构**。YOLOv7 的复合缩放方法正是专门为这类结构设计的。
